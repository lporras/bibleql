# SDKs

Three official clients wrap the API so you can call methods instead of writing GraphQL. All
three are MIT licensed and published.

| Language | Package | Source |
|---|---|---|
| Ruby | <a href={SDK.ruby.registry}><code>bibleql-ruby</code> on RubyGems</a> | <a href={SDK.ruby.repo}>lporras/bibleql-ruby</a> |
| Node.js / TypeScript | <a href={SDK.node.registry}><code>bibleql-js</code> on npm</a> | <a href={SDK.node.repo}>lporras/bibleql-js</a> |
| Python | <a href={SDK.python.registry}><code>bibleql</code> on PyPI</a> | <a href={SDK.python.repo}>lporras/bibleql-python</a> |

```ruby title="Gemfile"
gem "bibleql-ruby"
```

```bash title="npm"
npm install bibleql-js
```

```bash title="pip"
pip install bibleql
```

Then see [Configuring the SDKs](/sdks/configuration) for where to initialize the client.

There is also an <a href={SDK_EXAMPLES_REPO}>examples repository</a> showing the Ruby and Node
clients in use.

## All are server-side only

:::danger Never ship an API key to a browser
`bibleql-js` is built for Node.js and its README says explicitly not to use it in frontend
code. Bundling it into a browser app exposes your key to anyone who opens devtools.

If you need Bible text in a client application, call BibleQL from your own backend and proxy
the result.
:::

## Typed errors

All three map API failures to exception classes, so you can branch on type rather than
parsing messages:

| Condition | Ruby | Node.js | Python |
|---|---|---|---|
| Bad key | `BibleQL::AuthenticationError` | `AuthenticationError` | `bibleql.AuthenticationError` |
| Rate limited | `BibleQL::RateLimitError` | `RateLimitError` | `bibleql.RateLimitError` |
| Not found | `BibleQL::NotFoundError` | `NotFoundError` | `bibleql.NotFoundError` |
| Server error | `BibleQL::ServerError` | `ServerError` | `bibleql.ServerError` |
| Timeout | `BibleQL::TimeoutError` | `TimeoutError` | `bibleql.RequestTimeoutError` |
| Network failure | `BibleQL::ConnectionError` | `ConnectionError` | `bibleql.NetworkError` |
| GraphQL error | `BibleQL::QueryError` | `QueryError` | `bibleql.QueryError` |

See [Errors](/reference/errors) for the underlying wire format.

:::warning Check the default endpoint
The Ruby and Node SDKs currently default to a Render-hosted URL rather than
`https://bibleql.org/graphql`. The Python client already defaults to bibleql.org.
If you want to pin the canonical endpoint, set it explicitly — `api_url` in Ruby, `apiUrl` in
Node. Each SDK page shows how.
:::
